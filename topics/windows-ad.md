# Windows and Active Directory trouble

`recovery-access-and-directory-services-runbook.md` (sysadmin-windows) is the procedure when normal admin access to Windows Server or Active Directory is gone. `active-directory-reference.md` and `group-policy-reference.md` hold the day-to-day commands.

1. **Scope first.** One workstation, one server, one domain controller, a site, or the whole directory? Check DNS, time sync, network reachability, and the current DC role before resetting any password or changing group membership. A time, DNS, or replication failure often presents as an authentication failure.
2. **Record** the time, caller, affected account, error text, and last known good change. No broad password reset or forced replication until the blast radius is clear.
3. **Recovery flow.** Fix the clock first, since Kerberos is sensitive to skew. Verify DNS against the intended internal resolver, and never leave a domain member on a public resolver as a workaround. Use the console or an approved local admin path. For a user who cannot sign in, check account status, the group policy result, and DC availability before unlocking or resetting. Use a named emergency account only for the minimum repair. Keep the console open until ordinary access is confirmed from a known-good client, then remove temporary admin memberships and firewall exceptions.
4. **Fast health read.** `dcdiag /v` and `repadmin /replsummary` usually tell you whether "weird AD behavior" is a replication problem. `Test-ComputerSecureChannel -Repair` fixes a broken machine trust. `gpresult /h report.html /f` shows what policy a machine actually got.
5. **Safeguards.** Never restore a DC from a VM checkpoint as a routine rollback; use system-state recovery. Do not seize FSMO roles unless the holder is permanently gone and the decision is documented. Export the current state of privileged groups and GPOs before changing them. Treat DNS zones, SYSVOL, and time as first-class AD dependencies. Do not grant Domain Admin just to fix an application issue.
6. **Verify and follow up.** Test a standard user, a privileged user, and a service account. Check replication, DNS registration, time, event logs. Confirm the recovery did not disable monitoring or audit forwarding. Rotate any emergency credential that was used. Turn recurring checks into monitoring: replication health, DC backup age, privileged-group changes, break-glass sign-ins.

Prefer OU-linked GPOs with scoped security filtering over editing the Default Domain Policy. Break-glass prerequisites (two protected emergency accounts, console access to every DC, tested system-state backups) are in the runbook and summarized in `topics/break-glass.md`.
